# LodePNG 与头像标准化验收（2026-11-24）

基线 `da2f905a2514fea21508b9905271813900ad078e`；Ubuntu 22.04.5 x86_64，
GCC 16.0.1、Boost 1.92.0、Qt 6.5.3、CMake/Ninja。LodePNG 固定在
[`7b2893e35891c0c85bee5595caafaf3c2044b409`](../../../third/lodepng/README.chat.md)
（20261102，原样源文件及 zlib 许可证）。

## 实现与验收

- Qt 在原有 1 MiB 和像素数限制下读取 PNG/JPEG，同一入口用于个人和群头像。
  在新的 8 位图像上绘制居中裁切、平滑缩放的 256 × 256 像素；保留透明度，
  不篡改原图或复制其元数据。使用 Qt 原有 PNG 编码器。
- 服务端先 inspect 固定尺寸，再实际解码。显式检查所有 PNG chunk CRC（也包括
  未解释的辅助 chunk）、APNG 标记及最后的空 IEND；解码器默认校验 Adler-32。
  原生 zlib/DEFLATE 保留，辅助元数据的解压功能关闭。输出用保守的 16 位 RGBA
  加隔行滤波字节限制；上游的分配上限同时拒绝任何大于 1 MiB 的单次分配。
  这不是解码器总内存只有 1 MiB 的声明。
- 实际头像分块 RPC 验证 RGB/RGBA、跨 32 KiB 分片，并拒绝原始 JPEG、错误尺寸、
  超过 1 MiB、损坏 PNG 签名/IHDR、IDAT/辅助 chunk CRC、外层 CRC 正确但 Adler-32
  错误、截断的压缩流、缺失/损坏 IEND、尾随数据与动画标记。合法但解压长度超出
  头像规格的压缩及存储块测试分别在 1.75 / 1.54 ms 返回，原头像 BLOB 和 revision 不变。
- Qt 真实选择器验收非正方形透明 PNG、小图 JPEG、高分辨率 PNG、取消、无效文件、
  实际入库、原图不变、跨设备刷新、重启读取和清除。用旧数据夹具验证旧尺寸 PNG
  和 JPEG 继续读取。另验证群头像、与用户重号但各自存储、管理员上传中失权；
  各用一条 PNG 和 JPEG 聊天图片做 Qt／SDK／隔离 Silo 上传、原字节下载与预览。
- Debug 和 Release 的三个目标均构建，运行完整 `ops/acceptance/linux.sh`。
  新配置将 PNG/JPEG/ZLIB 的 CMake 查找禁用；没有卸载本机软件包。
  纯服务端空目录配置由 `strace` 查验无 IPv4/IPv6 调用。未操作登录桌面、
  Wayland／Portal 或生产数据，未重跑 4 GiB 专项。

实际链接命令显示只有服务端静态链接 LodePNG。服务端不再直接或间接加载
libpng、libjpeg 或 libz。Qt 自身的运行时依赖仍包含 libpng 和 zlib；PNG/JPEG
仍由原有 Qt 图片能力处理。这些运行时依赖不构成 Chat 构建对开发包的要求。

专项目录中使用 `CHAT_TEST_SERVER=/path/to/chat_server`，从 Release 构建用
`build_probe.py` 生成探针，再运行 `avatars.py <probe>` 与 `group_profiles.py <probe>`。
沿用隔离 Silo、临时数据库与独立 Xvfb/D-Bus。
