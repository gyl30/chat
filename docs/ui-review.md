## 一、正确性问题

### 1. 列表刷新后自动打开第一个会话并标为已读（实测）

`qt/src/chat_widget.cpp:1193-1195`：会话列表刷新时，如果当前没有打开的会话，代码会调用 `select_conversation(index(0,0))`；消息加载完成后 `mark_visible_messages()` 会上报已读。

| 场景 | 操作 | A 的读位 |
|---|---|---|
| 登录 | 只登录，不做任何点击 | 和 C 的私聊：0 → 3 |
| 当前会话消失后的下一次刷新 | C 删除和 A 的好友关系，当前会话关闭；之后 B 发来一个无关的好友申请 | 群：0 → 4 |

影响：未读在用户没有查看的情况下被清零，右侧聊天会自己切换。删除好友时 `contact_removed` 和 `friendship_changed` 会触发两次刷新（`main_window.cpp:560-590`），第二次刷新必然出现这个问题。静音、置顶、入群通过之后的刷新也一样。TUI 只移动选中项，不打开会话（`tui/src/app.cpp:307`），不受影响。

证据：[登录后](images/ui-review/auto-open-after-login.png)、[无关刷新后](images/ui-review/auto-open-after-refresh.png)、[读位数据](images/ui-review/auto-open-facts.json)。复现脚本：`tests/ui_review/repro_auto_open.py`。

### 2. 操作提示写进会话列表状态行，刷新即被清除（实测）

`chat_widget::set_error`（`chat_widget.cpp:1087`）改的是会话列表顶部的 `conversations_status_`，`set_conversations` 每次都会清空它（`chat_widget.cpp:1172`）。`main_window.cpp:700-701` 先发出 `get_conversations`，再显示「入群申请已通过」，刷新结果一到，提示就被覆盖。

实测：管理员通过申请后，在 0.05 秒到 2.6 秒之间截了 5 张图，都看不到这条提示，群直接出现在列表里，没有任何说明（[截图](images/ui-review/join-accepted-no-notice.png)）。同样走这条路径的还有「入群申请被拒绝」「收到新的入群申请」「已申请加入…」、静音或置顶失败、邀请链接无效、打开会话失败等提示；用户停在联系人页时，这些提示完全看不到。复现脚本：`tests/ui_review/repro_notice.py`。

### 3. 从联系人页打开聊天后，左栏不切换（实测）

`select_contact` → `open_chat`（`chat_widget.cpp:1589-1630`）这条路径没有调用 `show_conversations_section()`。右侧已经是聊天，左侧仍是联系人列表，会话列表里的选中高亮看不到（[截图](images/ui-review/contacts-open-chat-sidebar.png)）。资料对话框里的「消息」按钮也走同一条路径。微信点「发消息」会切到聊天页。

### 4. 主聊天窗口无法复制消息（代码）

消息右键菜单（`chat_widget.cpp:519-650`）没有「复制」，消息视图没有处理 Ctrl+C，委托绘制的气泡文字也不能选中。在 Qt 源码里搜索 `clipboard`，只有搜索对话框、邀请链接和用户名三处会写剪贴板。消息搜索对话框能「复制消息」（`message_search_dialog.cpp:118`），TUI 也能复制，只有主聊天窗口不行。

### 5. 消息搜索结果不能跳转到聊天位置（代码）

`message_search_dialog.cpp` 的结果列表只连接了右键复制，没有处理单击、双击或回车。用户只能看到孤立的匹配消息，无法回到原会话查看上下文。三家都支持从搜索结果跳转到对应消息。

### 6. 置顶消息定位失败时退回成文字搜索（代码）

`chat_widget.cpp:437-454`：置顶消息不在已加载的范围内时，会用它的首行文字打开搜索。文字可能匹配多条消息；置顶的是图片或文件时文字为空，搜索框打开后什么也没有。定位成功时也只是滚动过去，没有高亮。

### 7. 图片预览最多只有 640×480（代码）

`message_images.cpp:51` 的缓存和 `attachment_dialog.cpp` 的预览都缩放到 640×480 以内，「查看图片」看不到原图分辨率，窗口放大也没有用。只能先保存文件，再用外部程序查看。

### 8. 群里别人的消息也显示「已读 N 人」（截图）

`message_model.cpp:196-201` 的 `read_count_role` 只判断是不是群聊，没有判断是不是自己发的。他人的消息同样显示「已读 0 人」，信息噪声大，也容易让人以为能看到谁读了别人的消息。微信和 QQ 只对自己发的消息显示已读或未读，Telegram 只在自己的消息上显示勾（[截图](images/ui-review/auto-open-after-refresh.png)）。

### 9. 服务端英文错误原样显示在中文界面（截图）

登录时如果同一账号已经在线，登录页会显示 `User already online`。其他直接透传服务端错误字符串的地方很可能也有同样的问题，需要统一映射成中文提示。

### 10. 好友删除后草稿处理两端不一致（代码）

Qt 在会话从列表消失时删除草稿（`chat_widget.cpp:1149-1153`），TUI 会保留（`tui/src/app.cpp:304`）。重新加为好友后会话会恢复，但 Qt 的草稿找不回来。

### 11. 附件发送失败后回复引用丢失（代码）

`chat_widget.cpp:728-730` 在附件发出前就清空了 `reply_to_`，发送失败后引用无法恢复。文字消息在失败时会保留草稿和引用，附件与之不一致。

## 复现方法

两个脚本都会通过 `createdb` 新建一个临时库，依序应用 `sql/` 下的全部 migration，在独立端口启动 `chat_server`，用 `chat_tui_scale_fixture` 准备账号和关系，在 Xvfb 中运行 `chat_qt` 并截图，结束后删除临时库。需要先构建 `chat_server`、`chat_tui_scale_fixture`、`qt/chat_qt`，PostgreSQL 账号需要有建库权限，本机需要 Xvfb、xwininfo、xprop、xclip、libXtst 和 Pillow。

```sh
python3 -I tests/ui_review/repro_auto_open.py /tmp/ui-review-auto-open
python3 -I tests/ui_review/repro_notice.py /tmp/ui-review-notice
```

数据库连接沿用 libpq 环境变量，维护库固定为 `chat`。临时库名带时间戳，不会碰 `chat` 库里的业务数据。

## 最终验证（2026-10-08）

完整重编 0 个编译警告（`-Wall -Wextra -Wpedantic`）。`tests/verify.sh` 中 normal 构建 26/26 通过；ASan 构建 25/26，`tui_render` 以 5.02 秒超出 5 秒时限（直接运行成功退出，耗时 5.08 秒）；脚本因此在 ASan 处停止，UBSan 随后单独构建并运行，26/26 通过。

`tui_render` 的超时与本轮改动无关：本轮没有修改 TUI 代码，上一轮验证中它在 ASan 下已用 4.96 秒。[体验品质记录](experience-quality.md)曾将其优化到 ASan 4.06 秒，之后的 TUI 提交使其回到时限边缘，需要按当时的方式定位并优化，不放宽时限。
