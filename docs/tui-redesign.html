TUI 重新设计方案

让终端客户端用起来自然、好上手：全中文、能直接打字、操作看得见，业务分组和术语与 Qt 客户端一致。本文只是方案，尚未修改代码。

设计原则

全中文用词与 Qt 端一致。
能直接打字进入会话即可输入，不再需要按 i；输入时所有字符都是正文。
操作看得见底部常驻随焦点变化的按键提示；消息操作菜单标出快捷键。
少框线、多内容去掉嵌套框，只保留必要分隔线。
与 Qt 业务一致业务分组、术语和主要路径一致；布局按终端特点设计，不要求逐处相同。
不改变已读语义只有消息真正可见时才上报已读，浮层期间不上报。

焦点与按键作用域 新增

直接输入与单字母快捷键会冲突，所以先规定事件的分发顺序，按键只在当前所属的范围内生效。

事件分发顺序

  1. 最上层浮层独占事件：命令面板、帮助、消息菜单、确认框、资料或群信息覆盖页、账号浮层。浮层里的文本框（如命令面板搜索、确认输入）接收全部可打印字符；Tab 只在浮层内部的控件间循环；单字母别名和 : 都不响应。
  2. 登录与注册表单：与浮层相同，Tab 在表单字段之间循环，字符进入当前字段。
  3. 聊天工作区：没有浮层且已登录时，按下表的三种焦点分发。
工作区焦点可打印字符可用按键
输入框全部进入正文，包括 ? : / \ 和字母Enter 发送（编辑时为保存）；换行见下文；输入框为空时 ↑ 进入消息选择
消息选择作为快捷键↑↓/jk 移动，PgUp 加载更早消息，[ ] 逐行查看长消息，G 回到最新，Enter 打开操作菜单，单字母直接执行菜单中对应操作
列表作为快捷键↑↓/jk，PgDn 加载更多，Enter 打开，/ 搜索，m 免打扰，p 置顶会话

工作区通用按键

  • Ctrl+K 命令面板、F1 帮助：任何工作区焦点下都可打开，在浮层中也可打开（叠在上面）。关闭后焦点回到打开前的位置；从输入框打开时草稿和光标原样恢复。FTXUI 为两者提供独立事件，现有应用没有占用。
  • 非输入焦点下 ? 也打开帮助，: 英文命令保留为隐藏别名。
  • Tab / Shift+Tab：宽屏为 列表 → 消息选择 → 输入框 循环；窄屏只在消息选择与输入框之间切换，返回列表用 Esc。有草稿时用 Shift+Tab 从输入框进入消息选择，草稿保留。
  • Esc 依次执行第一项可做的事，每次只做一件：关闭最上层浮层 → 清除错误通知 → 取消编辑或回复（草稿保留）→ 退出消息选择回到输入框 → 从输入框回到列表（窄屏返回列表页）→ 在列表上不做任何事。

Tab 的迁移

现在 Tab / Shift+Tab 在会话列表与聊天页之间跳转，在新的朋友页切换「收到 / 发出」（ui.cpp:770）。阶段 2 只接管聊天工作区（会话列表与聊天页）里的 Tab；新的朋友页的 Tab 保持原样，直到阶段 5 把收到与发出合并为一个分组列表（与 Qt 一致）后再取消。

换行

Alt+Enter 不能作为唯一入口：当前 FTXUI 没有对应命名事件，需要识别原始序列；WezTerm 默认把它用于切换全屏；Ctrl+J 与 Enter 在 FTXUI 中同为 0x0a，不可用。
  • \ 后 Enter（阶段 2 交付，所有终端可用）。发送时不做任何反转义，只有这个换行操作会把一个反斜杠替换为换行：
    • 设置标记：在括号粘贴之外，输入框实际接收并插入了单个 Event::Character("\\") 时，记下「待换行标记」：所属会话、插入后的光标位置和当时的草稿内容。终端不区分物理按键与输入法提交，输入法提交的文本以 \ 结尾也按收到的字符处理。
    • Enter 时生效：标记有效、会话与草稿未变、光标仍在记录位置且其前一个字符是 \ 时，直接把这一个字符替换为换行，两侧正文不变，光标留在换行之后，并像普通编辑一样更新草稿与正在输入状态。不通过模拟 Backspace 再转发 Return 实现，因此 Insert 切换的覆盖模式下也不会多删字符。否则 Enter 照常发送。
    • 只消费一个：连续键入 \\\ 后 Enter，前两个保留，第三个变成换行。
    • 不清除标记：Custom 事件本身（重绘、通知到期、正在输入更新、inbox 唤醒）。但每次 OnEvent() 先执行 app_.drain()（ui.cpp:674），之后若会话、草稿或光标已被程序改变，标记失效。
    • 清除标记：除 Enter 之外的任何其他按键事件（包括没有实际移动光标的方向键、Tab、Esc、F1、Ctrl+K、Ctrl+Z 挂起）、括号粘贴的开始或结束（包括空粘贴）、焦点或会话切换、断线、发送。
    • 粘贴：括号粘贴仍在发送分支之前处理（ui.cpp:697），内容原样进入输入框，不设置标记；粘贴后按 Enter 即发送，即使内容以 \ 结尾。终端未启用括号粘贴时，无法区分粘贴与键入，粘贴里的换行本来就会作为 Enter 处理（现状），不在本规则保证范围。
    • 发送手动键入的结尾反斜杠：键入 \ 后按任意其他键（如 →）清除标记，再按 Enter 即发送。帮助中写明。
    • 回归用例：结尾单个与多个反斜杠；光标在正文中间；覆盖模式下正文中间换行；\ → Custom → Enter 仍换行；\ → 末尾无效方向键 → Enter 发送；空括号粘贴后 Enter；粘贴含反斜杠加换行；粘贴以一个或两个反斜杠结尾后 Enter；异步清空草稿后 Enter；切换会话再切回恢复草稿后 Enter 发送。阶段 2 不新增撤销功能。
    按键提示栏在输入焦点且没有通知时显示「\ Enter 换行」。
  • Alt+Enter（阶段 2 交付）：在验证过的终端上作为快捷入口，帮助中列出已验证终端。
  • 命令面板「插入换行」（阶段 4 补充）。
  • 多行粘贴：沿用现有括号粘贴处理，换行原样保留。

确认框

保留现有方式：标题带 [y/N]，输入 y 后按 Enter 才执行（app.cpp:425），不是按一次 y 立即确认。

已读、浮层与操作目标 新增

这部分会触及状态管理，不是只改界面。app.cpp:379 的页面切换会停止输入、递增页面版本并重置请求状态；messages.cpp:108 的已读判定依赖当前页面、是否在最新位置和弹窗状态；groups.cpp:20 的群回调会校验页面版本。

  • 已读：命令面板、消息菜单、帮助、资料或群信息覆盖聊天区，或窄屏下聊天区不可见时，一律不上报已读；浮层关闭后重新判定。底层页面保持「会话」也不能绕过这一条。
  • 稳定目标：消息菜单打开时绑定消息 ID，而不是列表位置；执行前再确认该消息仍存在、未删除、权限未变化，否则给出提示并取消。
  • 不改动：SDK、inbox 投递和连接与重连机制。
  • 新增回归：浮层期间来消息不被标记已读；浮层期间迟到的响应不切换页面；切换会话后上一会话发送完成不串到当前会话；浮层期间被移出群或解除好友时浮层安全关闭；断线重连后草稿保持。
  • 断线：沿用现有行为（app.cpp:191）：关闭浮层、清除回复与编辑状态、保留草稿。重连后原会话仍可访问时恢复到该会话；否则保存它的草稿、关闭会话并返回列表（现有 app.cpp:302）。不新增「恢复浮层」。

消息排版与合并规则

  • 只合并视觉信息：同一发送者的相邻消息只显示一次名字和时间，每条消息仍可单独选择和操作。
  • 开始新的一组：发送者变化、跨日期（插入日期分隔）、与上一条间隔超过 5 分钟、上一条为删除占位。
  • 引用、编辑、删除：引用以 ┃ 开头单独一行，不打断合并；「（已编辑）」始终附在对应消息的末尾，不随组头合并，组内第二条被编辑时也显示在那条消息上；删除显示「消息已删除」占位并结束当前组。
  • 视口顶部：若最上方可见消息是组内后续消息，在它上方补显发送者和时间，保证随时能看出是谁发的。
  • 分页：向上加载更早消息后重新计算分组，选中项与阅读位置保持不变。
  • 搜索结果：不合并，每条都显示发送者和时间。
  • 已读显示：单聊用「已读」文字；群聊保留「已读 N 人」，不以双勾替代。
  • Unicode：沿用 tui/cmake/README.md 描述的 utf8proc 字素处理和 DisplayWidth、Utf8ToGlyphs，中文、组合符、ZWJ、VS16 和 emoji 在换行、省略、选中、复制中逐项回归；单测通过不外推为所有终端正确。
