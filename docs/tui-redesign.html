让终端客户端用起来自然、好上手：全中文、能直接打字、操作看得见，业务分组和术语与 Qt 客户端一致。本文只是方案，尚未修改代码。

设计原则

全中文用词与 Qt 端一致。
能直接打字进入会话即可输入，不再需要按 i；输入时所有字符都是正文。
操作看得见底部常驻随焦点变化的按键提示；消息操作菜单标出快捷键。
少框线、多内容去掉嵌套框，只保留必要分隔线。
与 Qt 业务一致业务分组、术语和主要路径一致；布局按终端特点设计，不要求逐处相同。
不改变已读语义只有消息真正可见时才上报已读，浮层期间不上报。

焦点与按键作用域 新增

直接输入与单字母快捷键会冲突，因此先定义四种焦点上下文，按键只在所属上下文生效。

焦点可打印字符可用按键
输入框全部进入正文，包括 ? : / 和字母Enter 发送；换行见下文；输入框为空时 ↑ 进入消息选择
消息选择作为快捷键↑↓/jk 移动，[ ] 逐行查看长消息，G 回到最新，Enter 打开操作菜单，单字母直接执行菜单中对应操作
列表作为快捷键↑↓/jk、PgUp/PgDn、Enter 打开，/ 搜索，m 免打扰，p 置顶会话
浮层由浮层决定（命令面板、搜索框中为输入）菜单 ↑↓ Enter；确认对话框保留现有 y/N

任何焦点都可用的按键

  • Ctrl+K 命令面板：从输入框打开时保留草稿与光标，关闭后原样恢复。FTXUI 为它提供独立事件。
  • F1 帮助；非输入焦点下 ? 也打开帮助。
  • Tab / Shift+Tab 焦点循环：列表 → 消息选择 → 输入框 → 列表（窄屏不含列表）。有草稿时用 Shift+Tab 从输入框进入消息选择，草稿保留。
  • Esc 优先级：关闭最上层浮层 → 退出消息选择回到输入框 → 从输入框回到列表（窄屏返回列表页）→ 在列表上不做任何事。
  • : 英文命令保留为隐藏别名，仅在非输入焦点下响应。

换行

Alt+Enter 不能作为唯一的换行入口：当前 FTXUI 没有对应命名事件，需要识别原始序列；WezTerm 默认把它用于切换全屏；Ctrl+J 与 Enter 在 FTXUI 中同为 0x0a，不可用。
  • Alt+Enter：在验证过的终端上作为快捷入口，帮助中列出已验证终端。
  • 命令面板「插入换行」：所有终端都可用的保底入口。
  • 多行粘贴：沿用现有括号粘贴处理，粘贴内容中的换行原样保留。

新的朋友页的 Tab 冲突

现在用 Tab 在「收到 / 发出」之间切换，与焦点循环冲突。改为一个列表分两组显示（与 Qt 一致），不再需要切换。

已读、浮层与操作目标 新增

这部分会触及状态管理，不是只改界面。app.cpp:379 的页面切换会停止输入、递增页面版本并重置请求状态；messages.cpp:108 的已读判定依赖当前页面、是否在最新位置和弹窗状态；groups.cpp:20 的群回调会校验页面版本。

  • 已读：命令面板、消息菜单、帮助、资料或群信息覆盖聊天区，或窄屏下聊天区不可见时，一律不上报已读；浮层关闭后重新判定。底层页面保持「会话」也不能绕过这一条。
  • 稳定目标：消息菜单打开时绑定消息 ID，而不是列表位置；执行前再确认该消息仍存在、未删除、权限未变化，否则给出提示并取消。
  • 不改动：SDK、inbox 投递和连接与重连机制。
  • 新增回归：浮层期间来消息不被标记已读；浮层期间迟到的响应不切换页面；切换会话后上一会话发送完成不串到当前会话；浮层期间被移出群或解除好友时浮层安全关闭；断线恢复后浮层与草稿保持。

消息排版与合并规则

  • 只合并视觉信息：同一发送者的相邻消息只显示一次名字和时间，每条消息仍可单独选择和操作。
  • 开始新的一组：发送者变化、跨日期（插入日期分隔）、与上一条间隔超过 5 分钟、上一条为删除占位。
  • 引用、编辑、删除：引用以 ┃ 开头单独一行，不打断合并；已编辑在时间后标「已编辑」；删除显示「消息已删除」占位并结束当前组。
  • 视口顶部：若最上方可见消息是组内后续消息，在它上方补显发送者和时间，保证随时能看出是谁发的。
  • 分页：向上加载更早消息后重新计算分组，选中项与阅读位置保持不变。
  • 搜索结果：不合并，每条都显示发送者和时间。
  • 已读显示：单聊用「已读」文字；群聊保留「已读 N 人」，不以双勾替代。
  • Unicode：沿用 tui/cmake/README.md 描述的 utf8proc 字素处理和 DisplayWidth、Utf8ToGlyphs，中文、组合符、ZWJ、VS16 和 emoji 在换行、省略、选中、复制中逐项回归；单测通过不外推为所有终端正确。

可访问性与通知 新增

  • 不只靠颜色：焦点与选中项用反色加 › 标记；未读显示数字；置顶、免打扰、连接状态都有文字。
  • 通知生命周期：成功类通知约 5 秒后消失；错误保留到用户下一次操作或按 Esc。现有 status 是普通字符串，需要增加类型与到期时间（state.hpp:21、app.cpp:564）。
  • 验收：浅色终端、深色终端、无颜色（NO_COLOR）、纯键盘各走一遍主要流程。全屏终端的读屏效果需实际验证，不因支持键盘就视为完成。
  • 鼠标：首轮继续关闭，保留终端原生选中复制（main.cpp:43、ui.cpp:511）。若以后启用，单独交付点击、滚动、选中复制和终端模式恢复。
