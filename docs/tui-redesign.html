TUI 重新设计方案

让终端客户端用起来自然、好上手：全中文、能直接打字、操作看得见，并且和 Qt 客户端保持同样的结构。本文只是方案，尚未修改代码。

2026-10-08 · 依据：tui/src/ui.cpp 与 docs/images/experience/ 下的真实 tmux 截图

现状的问题

#问题例子
1中英文混用导航、按钮、群菜单是英文（Chats、Account、Show invite code、Esc: back），状态提示是中文（已连接、好友申请已更新），和 Qt 端也不一致
2框线和固定行太多，信息密度低顶部固定 3 行（应用名加用户名、connected、h Chats c Contacts u Account N New），每块内容再套一层框，底部再一行 Esc: back。账号页只有 4 个选项，下面空着 30 多行
3类 vim 的模式输入不符合直觉必须先按 i 才能打字；回复、编辑、删除、表情、复制、保存全靠记单字母（r e d a y s），还有大写 A/O/D、[ ]、G、: 命令，新用户发现不了
4会话列表信息不全一行只有 [连] 连续日常…，看不到时间、未读数、免打扰或置顶状态
5消息排版松散每条消息都重复「名字＋时间」，已读状态单独占一行，没有日期分隔，连续发言没有合并
6结构和 Qt 端不一致新的朋友、添加好友、群信息、账号各自是一整页，层层用 Esc 返回；Qt 端已改成右侧资料卡和统一搜索入口

设计原则

全中文用词和 Qt 端一致。
能直接打字进入会话即可输入，Enter 发送，不再需要按 i。
操作看得见底部常驻随焦点变化的按键提示；选中消息按 Enter 弹出操作菜单，菜单标出快捷键。
少框线、多内容去掉嵌套的框，只保留必要的分隔线。
结构对齐 Qt左边列表、右边详情；资料卡、群信息、账号用浮层或右侧面板，不再整页跳转。

示意图，实际为终端字符界面；颜色会跟随终端配色。

  • 顶部：两个标签页（聊天、联系人），带未读数或红点，下面是搜索框。原来固定的 3 行标题全部去掉。
  • 会话行：两行。第一行名字和时间，第二行最后一条消息预览和未读数；免打扰显示 🔕，置顶有标记；选中行左侧显示色条。
  • 消息区：按日期分隔；同一个人连续的消息只显示一次名字和时间；自己的消息靠右，时间后直接跟已读标记；引用以 ┃ 开头；附件显示为「[图片] 文件名 · 大小」。
  • 输入行：常驻，不再需要 i。
  • 状态栏：左边连接状态（● 已连接 / ○ 3 秒后重连），右边当前焦点可用的按键；临时通知也显示在这里，几秒后自动消失。
  • 窄屏（80～99 列）：只显示一栏。在列表按 Enter 进入会话，Esc 返回。

交互模型

场景按键
列表与会话之间切换焦点Tab / Shift+Tab；窄屏用 Enter 进入、Esc 返回
列表里移动↑↓（保留 j/k）、PgUp/PgDn、Home/End
会话里打字直接输入；Enter 发送；Alt+Enter 换行（多数终端无法区分 Shift+Enter）
选中某条消息输入框为空时按 ↑ 进入选择，再用 ↑↓ 移动；Esc 回到输入
对消息操作选中后按 Enter 弹出菜单：回复、复制、编辑、删除、表情、置顶、保存文件。菜单标出单字母快捷键，熟悉后可直接按
其他所有操作Ctrl+K 命令面板：输入中文或拼音首字母模糊搜索，例如添加好友、发起群聊、加入群聊、群信息、聊天记录、账号、退出登录。原来的 : 英文命令保留为隐藏别名
群信息 / 联系人资料在右侧面板显示，带操作按钮，Esc 关闭
帮助? 弹出分组的按键说明；首次登录时状态栏提示「按 ? 查看帮助」

各页面的调整

页面调整
联系人左侧标签页，和 Qt 一致：搜索框；输入内容后出现「查找用户“xxx”」；Enter 在右侧显示资料卡，操作随好友关系变化（发消息、添加、接受、拒绝、撤回）
新的朋友联系人标签页上用红点提示，通过命令面板或快捷键打开；申请行内直接按 y 接受、n 拒绝
群信息右侧面板，依次为成员（先显示前几位，可展开全部）、公告、邀请码（直接显示并可复制）、管理（仅群主和管理员可见）、退出群聊
账号小浮层：头像、复制用户名、退出登录，不再占一整页
聊天记录对应 Qt 的聊天记录窗口，分「全部 / 图片 / 文件 / 链接」，可直接搜索
登录中文；最近登录的账号直接填好（和 Qt 一致）；服务器设置折叠

分阶段实施

每个阶段单独提交，阶段末跑完整测试。

1
外观与排版：全中文化，精简标题栏和底部栏，状态栏与按键提示，会话列表两行，消息按发送人合并、加日期分隔
影响测试：tui_render 的文案与布局断言，tmux 冒烟脚本的匹配文字
2
交互模型：直接输入、焦点切换、消息操作菜单、命令面板、? 帮助
影响测试：tui_state、tui_integration、两个 tmux 冒烟脚本的按键序列
3
联系人与群：联系人、新的朋友、添加好友、资料卡、群信息面板，对齐 Qt
影响测试：tui_integration 与冒烟脚本中的好友、群流程
4
收尾：账号浮层、聊天记录、登录页；按 60～160 列、20～40 行逐一检查截图
影响测试：渲染与截图检查
风险主要在测试：现有 TUI 测试大量依赖英文文案和单字母按键序列，第 1、2 阶段需要同步改写不少断言。底层状态管理（SDK 回调、重连、草稿、并发保护）已经充分验证，这次只动界面层，不碰这部分。

需要决定的事项

  1. 鼠标：项目文档之前定过「TUI 不启用鼠标」。启用后可以点击列表行、菜单和按钮，FTXUI 支持，大多数终端也支持。
    建议：启用，但键盘仍是完整可用的主要方式。
  2. vim 风格按键（j/k、G 等）。
    建议：保留为别名，不在提示里显示，习惯它的人不受影响。
  3. 最小终端尺寸。
    建议：以 80×24 为下限，低于此尺寸只提示「请放大终端窗口」。
  4. 范围：四个阶段全做，还是先做第 1、2 阶段看效果再决定后面。
