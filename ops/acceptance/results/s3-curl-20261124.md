# S3 依赖替换验收（2026-11-24）

基线 `5488b3c3cffe5dd0f5b184042e5b29944f67a11a`，替换代码 `9ea31c8`。
Ubuntu 22.04.5 x86_64，GCC 16.0.1，Boost 1.92.0，Qt 6.5.3，OpenSSL 3.0.2。
GCC 16/Ninja Debug 和 Release 均构建 `chat_server`、`chat_client`、`chat_qt`。
两个空 Release 构建目录使用同一工具链和 `-j6`，串行构建各一轮；计时不含配置、下载、
验收和安装，不据此判定长期构建性能。

新静态归档 `libcurl.a` 为 1,709,774 B、`libchat_yxml.a` 为 21,566 B。
服务端和 Qt 均链接仓库内 curl；Yxml 仅进服务端。链接命令和 ELF 都没有系统
动态 libcurl 或旧 SDK；Qt、OpenSSL 和部分系统库仍动态链接。curl 和 Yxml 不发生配置下载。
两个被改写的附件文件连同新增签名、XML 和 curl 头文件，第一方行数合计从 684 增至
1,260；增量主要是以前由 SDK 提供的签名、XML 和 HTTP I/O 处理。

隔离真实 Chat、SDK、Qt、SQLite 和 Silo 验收通过：

- AWS 固定时间签名样例、PUT 参数编码、HTTP/HTTPS，自定义端口、桶和 `us-west-2`。
- 七种 S3 操作、签名 URL 900/120 秒、Content-MD5、ETag、首片 PUT 有效但确认丢失、
  Initiate 和 Complete 响应丢失；模拟 HTTP 200 文档内错误不会发布，已完成对象重试
  先 HEAD、只发布一遍。
- Qt 上传和下载精确 4 GiB，确认 256 片，最终 SHA-256
  `1f1de3c12707bef1de67d13f1f7a5a3511bf3e9666502617d42cd6a0f3f870c0`。
- 从旧版原安装的第 1 片续到新版，保留上传 ID 和本地任务记录，只确认第 2 片；
  排除其他安装、检查暂停/重启、15 天活动水位、群文件共享、撤回/失权及最后引用的回收。
- 下载流截断、重试、同名文件覆盖和清理；两条停顿下载取消约 0.82 / 0.89 s 关闭 socket，
  原阈值 3 s。HTTPS 正确 CA 通过，未知 CA 和错误主机名被拒绝。
  TLS PUT 已落片但响应停顿时，原 Qt 暂停后关闭 socket，恢复只需下一片；TLS GET 停顿退出也会清理。
- 原始 TCP 代理的下行及双向停顿；确认重连、既有 Outbox 与原安装续传、已撤销凭据拒绝。

Qt 使用离屏驱动并隔离应用数据、Xvfb 和 D-Bus。未操作登录桌面、生产环境或真实 AWS S3，
未测试其他对象存储后端。这是一轮本机构建与验收，不是 CI。
